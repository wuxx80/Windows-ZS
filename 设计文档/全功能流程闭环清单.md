**答案：有设计、且已在本轮（v0.0.268311-R1）完整落地到开发记录与客户端。**

现状梳理（如实）：

|----|--------------------------|----------------|------|

### 0.2 用户在 Windows 系统里选好安装流程后，无人值守一键安装后续如何自动完成？

**一句话答案：Windows 端只负责「下订单」（创建任务，状态置为 waiting，不碰磁盘）；机器重启进入 WinPE 后，PE 端自动从服务器拉取本机等待中的任务，按订单内容全自动完成分区→部署→装驱动→修引导→写无人值守应答→生成首次登录脚本→重启进新系统→首次登录自动装软件/优化。全程进度实时回传服务器。**

完整链路见第 2 章。

### 1.2 双端职责边界（关键决策，防止 Windows 端误操作磁盘）

| 能力 | Windows 端 | WinPE 端 |
|------|-----------|----------|
| 登录/连接服务器 | ✅ | ✅ |
| 客户端自注册（幂等） | ✅ | ✅ |
| 拉取镜像/磁盘 | ✅ | ✅ |
| 六步向导配置 | ✅ | ✅ |
| 创建装机任务 | ✅（状态=waiting） | ✅（直接 running） |
| 下载/校验镜像 | 仅提示 | ✅ 真实执行 |
| 分区/格式化 | ❌ 禁止（磁盘破坏性操作） | ✅ 真实执行 |
| 部署镜像 | ❌ 禁止 | ✅ 真实执行 |
| 注入驱动/修复引导 | ❌ 禁止 | ✅ 真实执行 |
| 写入无人值守应答 | ❌ 禁止 | ✅ 真实执行 |
| 生成首次登录脚本 | ❌ 禁止 | ✅ 真实执行 |
| 拉取本机待执行任务续装 | ✅ 不需要 | ✅ 启动时检测 |
| 重启进入 PE | ✅ 引导用户 | ✅ wpeutil reboot |
| 进度上报 | ✅ 仅到 waiting | ✅ running→completed/failed |

## 第 2 章 无人值守一键装机全链路（核心）

> 这是用户最关心的完整闭环。共 5 个阶段。

### 阶段 0：准备（后台一次性配置）

```
后台管理员（Layui 后台）
  ├─ 上传系统镜像（WIM/ESD/ISO/GHO，可选校验 SHA256）
  ├─ 配置无人值守模板（维修店标准/纯净办公/域加入…）
  ├─ 配置软件模板（办公标配/设计常用…）
  ├─ 配置驱动包（可选）
  └─ 审批客户端（第一次注册的客户端默认 pending，需 approve）
```

### 阶段 1：Windows 端下单（用户操作，2 分钟）

```
用户在 Windows 系统里双击「ZS 装机助手」
  ├─ 输入服务器地址 → 登录（admin/admin123，后续改为客户端独立凭证）
  ├─ 客户端自注册（幂等，复用 client_id）
  ├─ 首页点「一键装机」→ 打开六步向导
  │   ① 环境检测（网络/服务器/认证/PE识别/磁盘/启动模式…）
  │   ② 选择镜像（来源：服务器/远程URL/本地缓存/自定义源）
  │   ③ 选择目标磁盘 + 分区方案（自动/自定义/保留）
  │   ④ 安装选项（引导修复/无人值守/驱动注入/自动分区/备份/装软件/优化/激活/保留数据 + 扩展配置）
  │   ⑤ 确认（冲突检测：空间不足/PE盘/GPT-MBR 不匹配等）
  └─ ⑥ 开始装机
        → 调用 POST /api/v1/tasks 创建任务（含镜像、磁盘、分区方案、全部选项、无人值守模板ID）
        → 后台任务状态 = waiting（等待 PE 执行，绝不能在 Windows 端直接 completed）
        → Windows 端完成页提示：「任务已创建，请重启进入 WinPE 自动继续装机」
        → 提供「立即重启进入 PE」引导（提示用户用 U 盘/网络/本地 PE 分区引导）
```

**关键点：** Windows 端只下单，进度只报 5%（状态 waiting），不执行任何破坏性操作。

### 阶段 2：进入 WinPE（用户操作，1 分钟）

```
方式 A（推荐）：机器已有本地 PE 恢复分区 → Windows 端一键重启进 PE
方式 B：U 盘 PE 引导
方式 C：PXE 网络启动（后台网络部署模块）
```

### 阶段 3：WinPE 端自动续装（无人值守，全自动）

```
WinPE 启动 → ZS 装机助手自启动
  ├─ 连接服务器 → 客户端自注册（MAC 相同 → 复用同一 client_id）
  ├─ 自动查询本机等待中任务：GET /api/v1/tasks?client_id=本机&status=waiting
  ├─ 发现待执行任务 → 提示「检测到未完成的装机任务，是否继续？」[立即继续] [重新配置]
  ├─ 选择「立即继续」→ 自动预填向导（镜像/磁盘/选项全部来自任务订单）
  ├─ 跳过前四步，直接进入确认/执行
  └─ 开始执行（进度逐条实时回传）：
      1. 创建任务 → 认领任务（状态 waiting→running，记录 started_at）
      2. 下载镜像（未缓存则下载到 D:\ZS_Cache\images，支持断点续传）
      3. 校验镜像（SHA256）
      4. 备份数据（可选，按订单 backup_data）
      5. 分区/格式化（按订单分区方案；UEFI→GPT，Legacy→MBR）
      6. 部署镜像（DISM 应用 WIM/ESD 到目标分区）
      7. 注入驱动（按订单 driver_inject）
      8. 修复引导（bcdboot）
      9. 写入无人值守应答：C:\Windows\Panther\unattend.xml（由后台按模板生成，含自动应答/OOBE 跳过/首次登录命令）
      10. 生成首次登录脚本（按订单 install_software/optimize）：
          - C:\Windows\Setup\Scripts\SetupComplete.cmd
          - 或 RunOnce 注册表项 → 首次登录自动装软件、执行优化
      11. 上报 completed → 60 秒倒计时自动重启（wpeutil reboot）
```

### 阶段 4：首次进入新系统（无人值守，全自动）

```
新 Windows 首次启动
  ├─ 无人值守应答（unattend.xml）自动跳过 OOBE/密钥/区域设置
  ├─ SetupComplete.cmd / RunOnce 首次登录脚本自动执行：
  │    ├─ 静默安装软件（按订单软件模板：7-Zip/WPS/Chrome…，带静默参数）
  │    ├─ 应用系统优化（性能优化方案：服务/注册表/启动项/电源计划…）
  │    ├─ （可选）自动激活、加域、改计算机名
  │    └─ 完成后删除自身脚本（不留残留）
  └─ 用户看到：桌面就绪，软件已装好，优化已生效
```

### 阶段 5：后台全程可视

```
后台任务列表（Layui）
  ├─ 实时进度条（0-100%）+ 当前步骤 + 状态
  ├─ 任务日志（zs_task_records，每步一条）
  ├─ 客户端列表显示在线/离线（心跳 30s，3 次未到=离线）
  └─ 完成后装机次数 +1，报表统计
```

## 第 3 章 任务状态机与状态流转

### 3.1 任务状态定义

| 状态 | 含义 | 谁设置 | 说明 |
|------|------|--------|------|
| `pending` | 已创建，待认领 | 后台/客户端 create | Windows 端应直接置为 waiting（表示等待 PE）；后台手动创建默认 pending |
| `waiting` | 等待 WinPE 执行（新增） | Windows 端 create / 后台 | 订单已下，等待 PE 端认领 |
| `running` | 执行中 | WinPE 端认领/上报 | PE 认领时记录 started_at |
| `paused` | 已暂停 | 客户端/后台 | 仅 running 可暂停 |
| `completed` | 已完成 | PE 端 progress=100 | 装机真正完成才可置 completed |
| `failed` | 失败 | PE 端上报 failed | 记录 error_message |
| `cancelled` | 已取消 | 客户端/后台 | waiting/pending/running 可取消 |

### 3.2 状态流转图

```
                  ┌──────────┐
       create ──▶ │ pending  │
                  └────┬─────┘
                       │ (后台手动/重试)
                       ▼
                  ┌──────────┐   PE认领(claim/progress)   ┌──────────┐
 Windows下单 ───▶ │ waiting  │ ─────────────────────────▶ │ running  │
                  └──────────┘                            └────┬─────┘
                       │  cancel                                 │ pause
                       ▼                                         ▼
                  ┌──────────┐                          ┌──────────┐
                  │cancelled │                          │  paused  │
                  └──────────┘                          └────┬─────┘
                       ▲                                     │ resume
                       │ retry                               ▼
                  ┌──────────┐                          ┌──────────┐
                  │ failed   │◀─── progress(failed) ───│ running  │
                  └──────────┘                          └────┬─────┘
                                                            │ progress=100
                                                            ▼
                                                       ┌──────────┐
                                                       │completed │
                                                       └──────────┘
```

### 3.3 流转规则（后台强制校验）

| 当前状态 | 允许的操作 |
|----------|-----------|
| pending | 取消、重试、progress→running |
| waiting | 取消、progress→running（PE 认领） |
| running | 暂停、取消、progress 更新、progress→completed/failed |
| paused | 恢复 |
| completed | 无（终态） |
| failed | 重试、删除 |
| cancelled | 重试、删除 |

### 4.3 一键装机六步向导（双端共用，行为按端区分）

详细 UI/交互见《一键装机交互设计.md》v3.0。此处列出「每步的入口→校验→联动→出口」：

| 步骤 | 入口 | 校验 | 联动 | 出口 |
|------|------|------|------|------|
| ① 环境检测 | 进入自动执行 | 网络/服务器/认证/PE识别/磁盘/启动模式 | 失败项可单项修复/全部修复/强制继续 | 通过→②；失败→汇总面板 |
| ② 选择镜像 | 从服务器/URL/缓存/自定义源 | 必选一个镜像 | GHO 禁自动分区 | 选中→③ |
| ③ 目标磁盘 | 刷新磁盘列表 | 必选磁盘；PE 运行盘不可选 | 冲突检测（空间/GPT-MBR/PE盘） | 选中→④ |

## 第 6 章 各功能「入口→执行→退出→联动→状态」清单

### 6.1 客户端自注册（幂等闭环）

```
入口: 客户端连接服务器（登录成功后）→ POST /api/v1/clients/register
执行: ① 有 client_id → 按 client_id 匹配刷新心跳
      ② 无 client_id 但 MAC 匹配 → 复用（兼容 PE 重启）
      ③ 否则新建客户端（status=pending）
联动: 客户端保存返回的 id + client_id，后续所有请求带 Token
退出: 注册成功后进入主流程
状态: 服务端 pending→approved（后台审批）后才可派单
```

### 6.2 客户端心跳与离线判定（本轮新增）

```
入口: 客户端每 30s → POST /api/v1/clients/heartbeat
执行: ① 刷新 last_heartbeat/last_ip
      ② 返回: 客户端状态 + 本机待执行任务数 + 服务端最新配置变更标记
联动: 客户端按返回调整 UI（在线/离线/待审核/有任务）
状态: 后台列表查询时，last_heartbeat 超过 90s 自动判定 offline（不落库，仅展示）；
      3 次心跳失败客户端本地进入离线模式
```

### 6.3 创建装机任务（下单闭环）

```
入口: Windows 端确认页「开始装机」/ 后台任务列表新建
执行: POST /api/v1/tasks
      字段: image_id, client_id, target_disk_index, target_partition,
            partition_scheme, unattend_template_id, options(JSON 全部选项)
校验: 镜像存在 / 客户端存在且 approved / 参数合法
状态: Windows 下单 → waiting；PE 直接装机 → pending(随即 running)
退出: 返回 task_no，客户端进入完成页引导
```

### 6.4 任务认领/续装（PE 端闭环，本轮新增）

```
入口: WinPE 首页检测到本机 waiting 任务 → 用户点「立即继续」
执行: ① GET /api/v1/tasks?client_id=本机&status=waiting 取订单
      ② 预填向导（镜像/磁盘/分区/选项）
      ③ 开始执行 → progress(status=running) 触发 waiting→running
联动: 后台任务详情、客户端管理页面同步显示「执行中」
退出: completed/failed/cancelled
```

### 6.5 进度上报（双端闭环）

```
入口: 客户端每完成一步
执行: POST /api/v1/tasks/:id/progress {progress, step_name, message, status}
联动: 状态机流转（见第 3 章）+ 写 zs_task_records 日志
退出: completed（progress=100）/ failed
```

### 6.6 无人值守 XML 生成与应用（本轮补齐）

```
后台: 模板 CRUD（字段对齐 zs_unattend_templates: template_type/config/xml_content）
      → POST /api/v1/unattendTemplates/:id/generateXml 按 config 渲染真实 XML
      → 保存 xml_content
PE端: 部署完成后 GET /api/v1/tasks/:id/unattend（或任务详情带 xml）
      → 写入 C:\Windows\Panther\unattend.xml
      → 生成首次登录脚本（装软件/优化）C:\Windows\Setup\Scripts\SetupComplete.cmd
```

### 6.7 暂停/恢复/取消/重试（操作闭环）

| 操作 | 入口 | 后台校验 | 状态流转 |
|------|------|----------|----------|
| 暂停 | 执行页按钮 | 仅 running | running→paused |
| 恢复 | 执行页按钮 | 仅 paused | paused→running |
| 取消 | 执行页/后台 | waiting/pending/running | →cancelled |
| 重试 | 失败页/后台 | 仅 failed/cancelled | →pending（再次被认领） |
