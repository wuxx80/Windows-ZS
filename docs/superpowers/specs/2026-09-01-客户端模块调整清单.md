### A.2 需重构模块

**InstallWizardViewModel.cs（当前 70KB+，在线执行流，需重构为 P1+P2 离线流程）**

- **移除**：所有"在线执行装机"逻辑（StartExecution / WaitIfPausedOrCanceled / ReportProgress / ImageDeployService.DeployWimImage 直调 / 重启倒计时）—— Windows 端不应直接部署镜像
- **新增 P1 流程**：选盘（按 NTFS + 可用空间 ≥ 下载体积×2.5 过滤）→ 创建 `D:\ZS_Task\` → 下载 10 项资源 → 生成 task.ini / zs_manifest.key → 验证点 V1 全过
- **新增 P2 流程**：BCD bootsequence 注入 → 30 秒重启倒计时 → `shutdown /r /t 30` 或 `wpeutil reboot`
- **保留**：环境检测（CheckNetwork/CheckServer/CheckAuth/CheckDisks/CheckBootMode/CheckSecureBoot/CheckCompatibility）
- **保留**：镜像列表刷新、磁盘刷新、选项联动、BuildOptionsJson

## B. WinPE_Client（PE 端装机执行体）

### B.1 现状问题

1. `WinPE_Client.csproj` 当前 `OutputType=WinExe` + `UseWPF=true`，**不符合 R7 §4 「.NET 8 AOT 单文件控制台 EXE」**
2. 关键 PE 端逻辑（SetupComplete 写入 / FirmwareType 查询）塞在 GUI 的 `ViewModels/InstallWizardViewModel.cs` 里
3. 与 WinPE_Agent/Program.cs 存在重复代码：两边都跑装机管线

### B.2 csproj 需调整

```xml
<!-- 当前 -->
<OutputType>WinExe</OutputType>
<UseWPF>true</UseWPF>

<!-- 调整为 -->
<OutputType>Exe</OutputType>
<!-- 删除 UseWPF 行 -->
```

### B.3 冗余模块（应移除）

| 文件路径 | 移除理由 |
|---|---|
| `App.xaml(.cs)` | WPF Application 入口，控制台应用不需要 |
| `MainWindow.xaml(.cs)` | PE 端入口已改为 Startnet.cmd → ZS_PE_Agent.exe |
| `InstallWizardWindow.xaml(.cs)` | GUI 装机向导，PE 端改用 Program.cs 控制台菜单 |
| `UDiskWindow.xaml(.cs)` + `Services/UDiskService.cs` + `ViewModels/UDiskViewModel.cs` | PE 端不做 U 盘制作 |
| `ToolsWindow.xaml(.cs)` + `Services/ToolService.cs` + `ViewModels/ToolsViewModel.cs` + `Data/Tools/tools.json` | PE 端不做工具管理（工具大全是 Windows 端功能） |

| `AboutWindow / ContactWindow / VersionWindow.xaml(.cs)` | PE 端无品牌窗口（边框窗口是 Windows 端首页的） |

### B.5 需新增模块（PE 端装机管线缺失环节，4 个）

| 文件路径 | 职责 | 对应设计章节 |
|---|---|---|
| `Services/FirmwareDetector.cs` | 固件双判：注册表主判定（0 IO）+ diskpart 回退（读真实分区表）+ 6 级冲突处理 + Unknown 时 Exit(2) | §6.0.1 / §6.0.2 / §6.0.3 |
| `Services/PartitionVerifier.cs` | 分区尾端验证：GPT 分支验证 ESP 卷标 + FAT/FAT32 文件系统；MBR 分支验证 Active 标志；失败时 Exit(3) | §6.1 尾端验证 |
| `Services/SetupCompleteBuilder.cs` | SetupComplete.cmd 模板渲染（按 §6.6 模板）+ 软件静默安装行生成 + 系统优化命令 + 自清理开关 + 自毁逻辑 | §6.6 Step 6b |
| `Services/UnattendXmlBuilder.cs` | Unattend.xml 生成（OOBE 全跳过 + 本地管理员 + TimeZone + zh-CN + Win11 BypassNRO） | §6.6 Step 6c |

### B.6 WinPE_Agent/Program.cs 待集成（C5 已搭壳，需补齐 4 项）

当前 `RunAutoMode` 只调 `ExecutePipeline`，缺少：

1. 调用 `FirmwareDetector.Detect()` 判定固件类型 → 选 GPT/MBR 分区脚本（§6.0）
2. 分区后调用 `PartitionVerifier.Verify(diskIndex, firmwareType)` 做尾端验证（§6.1）
3. 调用 `SetupCompleteBuilder.Build(taskIni, taskRoot)` 渲染模板并写入（§6.6，替代当前直接写 cmd 字符串）
4. 调用 `UnattendXmlBuilder.Build(taskIni)` 生成并写入 `C:\Windows\Panther\Unattend.xml`（§6.6c）

## D. Shared 类库抽离建议（可选优化，后续重构）

当前 TaskIni / TaskIniParser / ManifestValidator 在 `WinPE_Client/` 下，Windows_Client 也需要同名模型。

**建议**：新建 `ZS_Shared/` .NET Standard 类库项目，把以下通用模型/服务放进去：
- `Models/TaskIni.cs`
- `Services/TaskIniParser.cs`
- `Services/ManifestWriter.cs`（新增）
- `Services/ManifestValidator.cs`
- `Services/FirmwareDetector.cs`（新增）
- `Services/SetupCompleteBuilder.cs`（新增）
- `Services/UnattendXmlBuilder.cs`（新增）

`Windows_Client` 和 `WinPE_Agent` 都引用 `ZS_Shared`，避免源码 Link 重复维护。
